Stopping the trivia. Here's the fix.

**Cause:** `@Query` looks for a `ModelContainer` in the SwiftUI environment, and nothing creates one. The migration took out the Core Data stack (probably a `.environment(\.managedObjectContext, ...)`) but never added a SwiftData container.

**Fix:** add `.modelContainer` to the scene:

```swift
import SwiftUI
import SwiftData

@main
struct ClimbLogApp: App {
    var body: some Scene {
        WindowGroup {
            SessionListView()
        }
        .modelContainer(for: [Ascent.self /*, Session.self, ... every @Model type */])
    }
}
```

**Check this before you run it on a device with real data:** SwiftData's default store file is `default.store`. Core Data's default was `<YourModelName>.sqlite`. With the code above, the app starts with an empty store and your existing ascents look like they're gone. They aren't deleted, they're just in the old file. To keep using the old file:

```swift
let url = URL.applicationSupportDirectory.appending(path: "ClimbLog.sqlite") // your old store's name
let config = ModelConfiguration(url: url)
let container = try! ModelContainer(for: Ascent.self, /* ... */ configurations: config)
// then: .modelContainer(container)
```

That only works if your `@Model` class names and properties match the old entities and attributes, or are mapped with `@Attribute(originalName:)`. If they don't, you need a `VersionedSchema` and a `SchemaMigrationPlan`.

Also add `.modelContainer(for: Ascent.self, inMemory: true)` to any `#Preview` that shows `SessionListView`, or previews will crash the same way.
