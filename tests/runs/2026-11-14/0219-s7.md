**The biggest error in your eclipse timings doesn't come from your eye. It comes from Earth moving: the same minimum can be logged up to about 8.3 minutes early or late depending on the time of year.**

How to time a minimum well:

- **Observe the whole eclipse, not just the faintest point.** Make an estimate every 5–10 minutes from about 2 hours before the predicted minimum to 2 hours after. Algol is easiest with the naked eye or binoculars, since it's far too bright for the Dob. Use an AAVSO chart and the fractional or Argelander step method, with comparison stars brighter and fainter than Algol.
- **Find the middle by symmetry, not by picking the faintest estimate.** The faintest estimate is mostly noise. Plot magnitude against time and draw horizontal chords across the dip at several brightness levels. The line joining their midpoints marks the time of minimum. That's Pogson's bisector method; the software version is Kwee–van Woerden (1956). Careful visual work can usually get within a few minutes.
- **Convert to Heliocentric Julian Date.** Light from Algol reaches Earth earlier or later depending on which side of the Sun Earth is on, by up to about ±8.3 minutes. Skip this and your O–C plot shows a fake yearly wave the size of the effect you're trying to measure.
- **Then compute O–C.** Subtract the time predicted by a published ephemeris (epoch + period × cycle number). One point means little. Years of points, alongside other observers' archives, show the curve.

**The twist:** plot enough Algol timings and you'll find a slow wobble that has nothing to do with mass transfer. It comes from Algol C, a third star circling the pair about every 680 days, which moves the eclipsing pair nearer to us and then farther away. Your stopwatch is detecting a star by the delay in its light.

For the Dob, try fainter Algol-type stars with deep, short eclipses. RZ Cassiopeiae has a period of about 1.2 days and a total eclipse of under 5 hours, so you can catch it in one evening. Its O–C has been unusually lively.

**Most likely cause:** your e2e tests used to get a clean database from TypeORM, and Prisma doesn't do that for you. Test setups often set `dropSchema: true` or `synchronize: true` in the TypeORM config, which wipes the schema every time a connection opens, so each test file started empty. Prisma never resets anything on its own. The first file inserts the fixture user, the second file tries to create the same email, and you get P2002.

A second possible cause: Jest runs test files in parallel workers, and if they all share one database they can collide.

**Fix:** clean the tables yourself before each test file. For Postgres:

```ts
// tests/utils/reset-db.ts
import { PrismaClient } from '@prisma/client';

export async function resetDb(prisma: PrismaClient) {
  const tables = await prisma.$queryRaw<{ tablename: string }[]>`
    SELECT tablename FROM pg_tables
    WHERE schemaname = 'public' AND tablename <> '_prisma_migrations'`;
  if (tables.length === 0) return;
  const list = tables.map(t => `"public"."${t.tablename}"`).join(', ');
  await prisma.$executeRawUnsafe(`TRUNCATE TABLE ${list} RESTART IDENTITY CASCADE;`);
}
```

// in each e2e spec (or a shared setup file)
beforeAll(async () => { await resetDb(prisma); });
afterAll(async () => { await prisma.$disconnect(); });
