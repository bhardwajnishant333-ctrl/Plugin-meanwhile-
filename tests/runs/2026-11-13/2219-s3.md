**Meanwhile (T1):**
**Once pg_upgrade finishes, your database has its data back, but it has forgotten what that data looks like.**

pg_upgrade only moves the schema (it uses `pg_dump --schema-only`) and then hard-links the data files when you pass `--link`. It doesn't carry over `pg_statistic`, the table where the planner keeps row counts, value distributions and most-common values. That's true of every version before PostgreSQL 18 (released September 2025), which finally keeps most of these statistics. Going from 14 to 16, you start with none. Until ANALYZE runs, the planner falls back on hardcoded default guesses. It might pick a nested loop over a table it thinks has a few hundred rows when the real number is 40 million. The usual first sign is a latency spike in the first hour, and it gets blamed on the new version.

The fix is the line pg_upgrade prints at the end and most people skip: `vacuumdb --all --analyze-in-stages`. It makes three passes, with the statistics target at 1, then 10, then the full value. The first pass takes seconds and gets the planner close enough to stop picking disastrous plans, and the later passes sharpen the numbers.

**The twist:** your agent's reindex step doesn't fix this. REINDEX rebuilds the index structure but doesn't fill in planner statistics for the tables. Autovacuum also won't step in reliably, because it starts an analyze based on how many rows have changed since the last one. A table that mostly gets read can go unanalyzed for a long time. **A line of perfectly rational people can all make the same wrong choice, and each of them is right to.**

The classic setup has two urns: one mostly red balls, one mostly blue. Each person privately draws a ball that matches the true urn 70% of the time, then announces a guess, in order, and everyone hears the earlier guesses. Suppose the first two people both say "red". The third person draws blue, but two red guesses outweigh one private blue draw, so the rational move is to say "red" and ignore their own ball. From that point everyone does the same. No new information gets into the public record, because nobody's guess shows what they actually drew.

The cascade locks in once one answer leads by two, so the first couple of signals decide it. With 70% accurate signals, the chance of locking into the wrong answer is (0.3²)/(0.7² + 0.3²), about 16%.
